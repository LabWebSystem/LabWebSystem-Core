# タスク

## 目的
`docs` 配下に分散しているドキュメントを全件分析し、現行実装と現行運用に一致する正式仕様書へ統合する。

## 要求
- 細かなバグ修正ログ、単発の修正履歴、現行実装と食い違う記述は正式仕様から除外する。
- 仕様判断は「現在の実装コード」を最優先とする。
- ドキュメント同士が競合する場合は、作成日時が新しいものを優先する。
- 以下の成果物を `docs/<作成日時+短いトピック名>/` に保存する。
  - `task.md`
  - `implementation_plan.md`
  - `walkthrough.md`
  - 正式仕様書（本整理で新規作成）

## 完了条件
- 現行のコマンド体系、設定方法、API、運用手順が1つの正式仕様書で追える。
- 過去ログ性の情報は「正規仕様」から切り離されている。
- 採用/非採用の判断基準が `walkthrough.md` に明記されている。
