# ダッシュボード機能要素整理

## 目的

この文書は、現行ダッシュボードが持つ機能を、画面構成や文言配置から切り離して抽象化したものである。  
UI を再構成する際に必要となる「何を入力し」「バックエンドで何を行い」「何を返し」「何を表示すべきか」だけを整理する。

## 共通して必要な基盤機能

### システム状態の取得機能

- システム全体の状態を取得する機能がある。
- この機能は追加の入力を必須とせず、バックエンドに現在の実行状態の取得を要求する。
- バックエンドからは、実行モード、ルートドメイン、アプリ集計情報などの運用状態が返る。
- フロントエンド側には、最新状態を表示する部分と、一定間隔または再フォーカス時に再取得する仕組みが必要である。

### アプリ集合の取得機能

- 管理対象アプリの集合を取得する機能がある。
- この機能は追加の入力を必須とせず、バックエンドに登録済みアプリ一覧の取得を要求する。
- バックエンドからは、各アプリの識別子、名前、説明、公開先、状態、更新状況、ヘルス情報などが返る。
- フロントエンド側には、複数アプリの概要を比較できる表示部分と、個別対象を選択する導線が必要である。

### イベント履歴の取得機能

- システムやアプリに関するイベント履歴を取得する機能がある。
- この機能は件数上限を数値で受けとり、バックエンドに新しいイベントの取得を要求する。
- バックエンドからは、発生時刻、重要度、対象範囲、関連アプリ名、要約、本文などが返る。
- フロントエンド側には、時系列表示と、重要度に応じた区別表示が必要である。

### ジョブキューの取得機能

- 非同期処理の待機・実行・失敗状況を取得する機能がある。
- この機能は件数上限を数値で受けとり、バックエンドにジョブ一覧の取得を要求する。
- バックエンドからは、ジョブ識別子、種別、状態、関連対象、メッセージ、作成時刻、開始時刻、終了時刻などが返る。
- フロントエンド側には、ジョブの現在状態、経過時間、失敗有無を一覧できる部分が必要である。

### 明示的な再取得機能

- 利用者の操作で全体情報を再取得する機能がある。
- この機能は明示的な再取得要求のみを入力として受けとり、バックエンドから各種最新情報を再取得する。
- バックエンドからは、上記のシステム状態、アプリ集合、イベント、ジョブが更新された形で返る。
- フロントエンド側には、処理中表示と、再取得完了後の画面更新が必要である。

### 処理結果通知機能

- 各操作の成功・失敗を短時間表示する機能がある。
- この機能は各処理の結果文字列を入力として受けとる。
- バックエンド処理そのものは行わず、他機能の実行結果を表示に反映する。
- フロントエンド側には、成功通知と失敗通知を区別して一定時間表示する部分が必要である。

## 監視・把握のための機能

### 重要アプリの抽出機能

- 状態やヘルス情報から、注意が必要なアプリを抽出する機能がある。
- この機能は取得済みアプリ集合を入力として受けとる。
- バックエンド追加呼び出しは必須ではなく、フロントエンド側で既存データから判定できる。
- フロントエンド側には、優先度の高い対象を先に見せる表示部分が必要である。

### 最近追加されたアプリの抽出機能

- 登録日時を基準に新しいアプリを抽出する機能がある。
- この機能は取得済みアプリ集合を入力として受けとる。
- バックエンド追加呼び出しは必須ではなく、フロントエンド側で並べ替えできる。
- フロントエンド側には、最近追加された対象へ素早く移動できる表示部分が必要である。

### 失敗ジョブの抽出機能

- 失敗状態のジョブだけを抽出する機能がある。
- この機能は取得済みジョブ集合を入力として受けとる。
- バックエンド追加呼び出しは必須ではなく、フロントエンド側で状態による絞り込みを行う。
- フロントエンド側には、失敗理由の要約と対象への導線を示す部分が必要である。

## アプリ登録のための機能

### 登録元解析機能

- 外部リポジトリの登録元情報を解析する機能がある。
- この機能はリポジトリ URL を文字列で受けとり、バックエンドに解析要求を送る。
- バックエンドでは、URL 正規化、利用ブランチの解決、リポジトリ内ファイル収集、定義ファイル探索、マニフェスト解析を行う。
- バックエンドからは、正規化済み URL、解決済みブランチ、候補ブランチ、ファイル一覧、YAML 一覧、compose 候補、推奨 compose、マニフェスト内容、警告情報が返る。
- フロントエンド側には、解析途中の状態表示、解析結果の要約表示、警告表示が必要である。

### 構成ファイル解析機能

- コンテナ構成ファイルを解析して公開候補を抽出する機能がある。
- この機能はリポジトリ URL、ブランチ名、対象ファイルパスを文字列で受けとり、バックエンドに解析要求を送る。
- バックエンドでは、対象ファイルの取得、YAML 解析、サービス抽出、公開ポート推定、環境変数要件抽出、デバイス要件抽出を行う。
- バックエンドからは、解析済みサービス候補、推定公開ポート、環境変数要件、デバイス要件、解析警告、解析エラー、元 YAML、構造化結果が返る。
- フロントエンド側には、候補選択、解析エラー表示、追加の詳細確認表示が必要である。

### 登録内容編集機能

- 新規アプリ登録に必要な内容を利用者が編集する機能がある。
- この機能は名前、説明、リポジトリ URL、ブランチ名、構成ファイルパス、公開サービス名、公開ポート、公開先ホスト名、実行モード、再構築時のデータ保持設定、デバイス要件、環境変数上書き値を入力として受けとる。
- バックエンド追加呼び出しは必須ではなく、送信前の編集内容を保持する。
- フロントエンド側には、文字列入力、数値入力、真偽値入力、列挙選択、複数キーの上書き入力を扱える部分が必要である。

### 新規登録実行機能

- 新規アプリを登録する機能がある。
- この機能は登録内容編集機能で集めた各入力値を受けとり、バックエンドに登録要求を送る。
- バックエンドでは、登録内容の検証、アプリ定義の保存、デプロイ準備、関連ジョブの生成を行う。
- バックエンドからは、登録されたアプリ識別子や処理開始結果が返る。
- フロントエンド側には、送信中表示、入力リセット、登録後に対象の状態確認へ移る導線が必要である。

## アプリ運用のための機能

### 個別アプリ詳細取得機能

- あるアプリの詳細状態を取得する機能がある。
- この機能はアプリ識別子を文字列で受けとり、バックエンドに詳細取得を要求する。
- バックエンドからは、基本情報、運用状態、ヘルス詳細、イベント履歴、関連ジョブ、デプロイ設定、構成ファイル解析結果などが返る。
- フロントエンド側には、対象アプリの現在状態と編集可能情報をまとめて表示する部分が必要である。

### アプリ停止機能

- アプリを停止する機能がある。
- この機能はアプリ識別子を文字列で受けとり、バックエンドに停止要求を送る。
- バックエンドでは停止ジョブを生成し、非同期に停止処理を進める。
- バックエンドからは、即時完了ではなく、ジョブ開始に関する結果が返る。
- フロントエンド側には、進行中ジョブの表示と、競合操作を抑止する仕組みが必要である。

### アプリ再開機能

- 停止済みアプリを再開する機能がある。
- この機能はアプリ識別子を文字列で受けとり、バックエンドに再開要求を送る。
- バックエンドでは再開ジョブを生成し、非同期に起動処理を進める。
- フロントエンド側には、ジョブ開始の通知と、その後の状態反映が必要である。

### アプリ再起動機能

- アプリを再起動する機能がある。
- この機能はアプリ識別子を文字列で受けとり、バックエンドに再起動要求を送る。
- バックエンドでは再起動ジョブを生成し、停止と起動を伴う処理を非同期に進める。
- フロントエンド側には、処理開始通知と進行状態表示が必要である。

### アプリ再構築機能

- アプリを再構築する機能がある。
- この機能はアプリ識別子と、データ保持の真偽値を受けとり、バックエンドに再構築要求を送る。
- バックエンドではイメージ再構築や再デプロイを伴うジョブを生成する。
- フロントエンド側には、データ保持条件を前提とした処理開始表示が必要である。

### 更新確認機能

- 更新可能性を確認する機能がある。
- この機能はアプリ識別子を文字列で受けとり、バックエンドに更新確認要求を送る。
- バックエンドでは参照先の更新有無を確認するジョブを生成する。
- フロントエンド側には、確認開始通知と、その後の更新有無反映が必要である。

### 更新適用機能

- 既存アプリへ更新を適用する機能がある。
- この機能はアプリ識別子を文字列で受けとり、バックエンドに更新適用要求を送る。
- バックエンドでは更新ジョブを生成し、必要な取得・再配置・反映を非同期に進める。
- フロントエンド側には、進行中状態と完了後の状態反映が必要である。

### ロールバック機能

- 以前の状態へ戻す機能がある。
- この機能はアプリ識別子を文字列で受けとり、バックエンドにロールバック要求を送る。
- バックエンドでは以前の参照点を用いた復旧ジョブを生成する。
- フロントエンド側には、ロールバック可能条件の判定表示と、処理開始後の進行表示が必要である。

### アプリ削除機能

- アプリ登録を削除する機能がある。
- この機能はアプリ識別子、削除モード、確認用文字列を受けとる。
- バックエンドでは削除モードに応じて、設定のみ削除するか、実体も含めて削除するかを判断し、削除ジョブを生成する。
- バックエンドからは、削除処理開始結果が返る。
- フロントエンド側には、誤操作防止の確認入力、削除範囲の選択、処理開始通知が必要である。

## デプロイ設定編集のための機能

### 現在設定の読込機能

- 対象アプリの現在デプロイ設定を読込む機能がある。
- この機能はアプリ識別子を文字列で受けとり、バックエンドに詳細取得を要求することで設定情報を得る。
- バックエンドからは、構成ファイルパス、公開サービス名、公開ポート、ホスト名、データ保持設定、環境変数上書き値などが返る。
- フロントエンド側には、編集前の初期値を保持し、未保存変更の有無を判定する仕組みが必要である。

### 既存アプリ向け構成ファイル再解析機能

- 既存アプリに紐づく構成ファイルを再解析する機能がある。
- この機能はアプリ識別子と対象ファイルパスを文字列で受けとり、バックエンドに解析要求を送る。
- バックエンドでは対象構成ファイルの取得、YAML 解析、サービス候補抽出、環境変数要件抽出を行う。
- バックエンドからは、候補ファイル一覧、YAML 一覧、サービス候補、解析警告、解析エラー、環境変数要件が返る。
- フロントエンド側には、候補の切替、推奨候補の反映、解析結果の確認表示が必要である。

### デプロイ設定編集機能

- 既存アプリの公開設定や上書き値を編集する機能がある。
- この機能は構成ファイルパス、公開サービス名、公開ポート、公開先ホスト名、データ保持設定、環境変数上書き値を入力として受けとる。
- バックエンド追加呼び出しは必須ではなく、保存前の編集内容を保持する。
- フロントエンド側には、編集状態の保持、未保存変更の表示、元に戻す操作が必要である。

### デプロイ設定保存機能

- 編集済みデプロイ設定を保存する機能がある。
- この機能は編集後の設定値を受けとり、バックエンドに更新要求を送る。
- バックエンドでは入力値の検証、設定保存、以後のデプロイ反映対象の更新を行う。
- バックエンドからは、更新完了結果が返る。
- フロントエンド側には、入力検証、解析エラー時の送信抑止、保存成功後の再読込が必要である。

## ログ確認のための機能

### ログ対象サービス取得機能

- ログ取得対象となるサービス名集合を取得する機能がある。
- この機能はアプリ識別子を文字列で受けとり、バックエンドに取得要求を送る。
- バックエンドからは、ログ取得可能なサービス名の配列が返る。
- フロントエンド側には、対象サービス選択のための入力部が必要である。

### ログ取得機能

- 実行中アプリのログを取得する機能がある。
- この機能はアプリ識別子に加えて、任意のサービス名文字列と取得行数の数値を受けとり、バックエンドにログ取得要求を送る。
- バックエンドでは対象サービスのログ末尾を取得し、行配列と取得時刻を返す。
- バックエンドからは、ログ本文の行配列と取得時刻が返る。
- フロントエンド側には、ログ本文表示、取得時刻表示、自動再取得、スクロール追従の制御が必要である。

## ジョブ運用のための機能

### ジョブ再実行機能

- 失敗済みまたは再試行可能なジョブを再実行する機能がある。
- この機能はジョブ識別子を文字列で受けとり、バックエンドに再実行要求を送る。
- バックエンドでは対象ジョブの再投入または同等ジョブの新規生成を行う。
- フロントエンド側には、再実行開始通知と、キュー状態更新が必要である。

### ジョブ取消機能

- 待機中ジョブを取り消す機能がある。
- この機能はジョブ識別子を文字列で受けとり、バックエンドに取消要求を送る。
- バックエンドでは未実行ジョブの状態更新を行う。
- フロントエンド側には、取消可能条件の判定と、状態変化の反映が必要である。

### ジョブ削除機能

- 履歴または不要ジョブをキュー表示対象から取り除く機能がある。
- この機能はジョブ識別子を文字列で受けとり、バックエンドに削除要求を送る。
- バックエンドでは対象ジョブの削除または非表示化相当の処理を行う。
- フロントエンド側には、削除可能条件の判定と、一覧更新が必要である。

## インフラ同期のための機能

### 外部公開設定同期機能

- 名前解決や公開経路に関わる設定を同期する機能がある。
- この機能は実行理由を表す文字列を受けとり、バックエンドに同期要求を送る。
- バックエンドでは DNS やリバースプロキシなどの関連設定を再生成または同期する。
- バックエンドからは、同期処理開始または完了結果が返る。
- フロントエンド側には、明示実行の導線と、完了通知が必要である。

## UI 再構成時に最低限残すべき入力要素

- リポジトリ URL を受けとる文字列入力
- ブランチ名を受けとる文字列入力
- 構成ファイルパスを受けとる文字列入力または候補選択
- 公開サービス名を受けとる文字列入力または候補選択
- 公開ポートを受けとる数値入力
- 公開先ホスト名を受けとる文字列入力
- 実行モードを受けとる列挙選択
- データ保持可否を受けとる真偽値入力
- デバイス要件を受けとる文字列入力
- 環境変数上書き値を受けとるキーごとの文字列入力
- 削除モードを受けとる列挙選択
- 削除確認用文字列を受けとる文字列入力
- ログ対象サービスを受けとる文字列選択
- ログ取得行数を受けとる数値入力

## UI 再構成時に最低限残すべき表示要素

- システム状態の最新表示
- 管理対象アプリ集合の要約表示
- 個別アプリの詳細状態表示
- イベント履歴表示
- ジョブキュー表示
- 非同期処理の進行状況表示
- 成功・失敗通知表示
- 構成ファイル解析結果表示
- ログ本文表示
- 未保存変更や入力エラーの表示
