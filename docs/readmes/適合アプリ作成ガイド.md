# 適合アプリ作成ガイド

対象読者:
- Lab-Core に新しい Web アプリを登録したい開発者

文書ステータス:
- current

最終更新日:
- 2026-06-07

## 1. 目的
このガイドは、Lab-Core に安全に載せられる GitHub リポジトリを最短で作るための説明書です。

## 2. 先に押さえる必須条件
1. Git で clone 可能なリポジトリであること
2. `docker compose -f <composePath> up -d --build` が成功すること
3. 公開対象サービス名が compose に存在すること
4. 公開対象ポートで HTTP を listen すること
5. `restart` / `down` / `logs` が通ること
6. ログが stdout / stderr に出ること

## 3. 推奨リポジトリ構成
```text
my-app/
├── docker-compose.yml
├── Dockerfile
├── .dockerignore
├── .env.example
├── README.md
└── src/...
```

## 4. Compose の基本ルール
- 公開対象サービス名を固定する
- アプリ内部の listen ポートを明示する
- 依存サービスは同じ compose に含める
- 永続データはコンテナ外へ切り出す
- 本番に不要な開発専用 profile 依存を避ける

標準 Web の例:
```yaml
services:
  web:
    build:
      context: .
      dockerfile: Dockerfile
    restart: unless-stopped
    environment:
      PORT: "3000"
    expose:
      - "3000"
```

登録時の対応値:
- `publicServiceName`: `web`
- `publicPort`: `3000`
- `mode`: `standard`

## 5. データ永続化
`LAB_CORE_APPS_ROOT=./runtime/apps` と `LAB_CORE_APPDATA_ROOT=./runtime/appdata` の構成では、clone 先から見て `../../appdata/<app>` を使うとソースとデータを分離できます。

```yaml
services:
  web:
    volumes:
      - ${APPDATA_ROOT:-../../appdata/my-app}:/var/lib/my-app
```

## 6. README に必ず書く項目
1. 公開対象サービス名と公開ポート
2. `docker compose up -d --build` の実行方法
3. 必須環境変数
4. 永続データの保存先
5. デバイス要件の有無
6. 障害時の確認コマンド

## 7. 登録前の自己チェック
```bash
docker compose -f docker-compose.yml config --services
docker compose -f docker-compose.yml up -d --build
docker compose -f docker-compose.yml logs --no-color --tail 200
docker compose -f docker-compose.yml restart
docker compose -f docker-compose.yml down
```

## 8. SDK を使う場合
Lab-Core 用 SDK を使うと、雛形生成・適合性確認・profile ごとの設定分離をまとめて扱えます。`labcore init` で生成される `labcore/SDK使い方.md` を起点にしつつ、詳細は `docs/readmes/SDK概要.md` と `docs/readmes/SDK仕様書.md` を参照してください。
