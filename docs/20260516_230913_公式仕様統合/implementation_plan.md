# 実装計画

## 方針
- 仕様の正: `package.json` / `scripts` / `core/backend` / `core/dashboard` の現行コード。
- 補助根拠: `docs` 既存文書（ただし新しい更新を優先）。
- 除外対象: 修正ログ、過去フェーズの作業記録、現行コマンド体系と不一致の運用説明。

## 手順
1. `docs` 配下の全ファイルを棚卸しし、更新時刻と文書種別を整理する。
2. 現行コードから以下を確定する。
   - 公開コマンド体系
   - `.env` 設定フロー
   - API とジョブ処理
   - UI 操作フロー
   - DNS/Proxy 同期仕様
3. 既存ドキュメントの内容を以下で判定する。
   - 採用: 現行コードと整合し、かつ新しい更新で裏付けがある記述
   - 非採用: 修正ログ、旧コマンド、旧運用、理想案のみの記述
4. 正式仕様書を新規作成する。
5. 本作業の判断根拠と差分を `walkthrough.md` に記録する。

## 品質観点
- 仕様書のコマンド名が `package.json` の現行 scripts と一致すること。
- API 記述が backend 実装ルートと一致すること。
- 運用手順が `dry-run` / `execute` の実装挙動に一致すること。
