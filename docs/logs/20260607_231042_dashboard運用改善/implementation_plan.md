# 実装計画

## 目的

ダッシュボードを「一覧を見る画面」から「運用判断と安全な操作を行う画面」へ引き上げる。

## 方針

1. バックエンドに運用判断用の情報を追加する。
   - アプリごとのヘルスチェック結果
   - アクティブジョブの検出
   - 失敗ジョブの再実行
   - 待機中ジョブのキャンセル
   - 競合操作の拒否

2. 画面上の状態表現を整理する。
   - 生の `status` は保持しつつ、UI 側で日本語ラベルと表示トーンを定義する
   - ジョブ種別、ジョブ状態、ヘルス状態を別軸で表示する
   - 「デプロイ」に文言統一する

3. 一覧・詳細・追加画面を V1 向けに再構成する。
   - ホーム: 注意アプリ、進行中ジョブ、失敗ジョブ、最近のイベントを集約
   - 一覧: ヘルス、アプリ状態、アクティブジョブ、更新有無をカード表示
   - 詳細: 状態カード、アラート、ジョブ履歴、デプロイ設定、ログ、削除導線を整理
   - 追加: 「アプリを追加する」に変更し、追加後は一覧へ戻す

## 状態整理

### アプリ状態

| 内部状態 | 画面表示 | 意味 | 主な操作 |
| --- | --- | --- | --- |
| `Build Pending` | 追加受付済み | 登録済み、初回デプロイ待ち | 詳細確認 |
| `Cloning` | 取得中 | リポジトリ取得中 | 詳細確認 |
| `Deploying` | デプロイ中 | 初回/再開/更新/停止系の処理中 | 危険操作を無効化 |
| `Running` | 稼働中 | 現在公開中 | 停止、再起動、更新確認 |
| `Degraded` | 注意 | 稼働中だが要確認 | 詳細確認、ログ確認 |
| `Stopped` | 停止中 | 意図的に停止 | 再開 |
| `Failed` | 失敗 | 直近処理が失敗 | 失敗ジョブの再実行、ログ確認 |
| `Rebuilding` | 再構築中 | 再ビルド/ロールバック中 | 危険操作を無効化 |
| `Deleting` | 削除中 | 削除ジョブ進行中 | 他操作不可 |

### ジョブ状態

| 内部状態 | 画面表示 | 意味 | 操作 |
| --- | --- | --- | --- |
| `queued` | 待機中 | 作成済みだが未開始 | キャンセル可 |
| `running` | 実行中 | 現在進行中 | 原則キャンセル不可 |
| `succeeded` | 成功 | 正常完了 | 履歴参照 |
| `failed` | 失敗 | エラー終了 | 再実行可 |
| `cancelled` | キャンセル | 待機中に取り消し | 履歴参照 |

### ヘルス状態

| 内部状態 | 画面表示 | 判定 |
| --- | --- | --- |
| `healthy` | 正常 | URL 応答正常、コンテナ状態安定 |
| `slow` | 遅延 | 応答遅延、または一部状態確認中 |
| `page_error` | 画面確認 | URL 到達可だが 4xx 応答 |
| `runtime_error` | 異常 | 5xx 応答、またはコンテナ異常 |
| `unreachable` | 到達不可 | URL 接続失敗 |
| `pending` | 処理中 | デプロイ系処理中のため評価保留 |
| `stopped` | 停止 | 意図的停止中 |
| `unknown` | 未確認 | 監視に必要な情報不足 |

## 実装対象

- `core/backend`
  - スキーマ拡張
  - ジョブ再実行・待機キャンセル API
  - アプリ操作の排他制御
  - 内部 Compose プロジェクト名の一意化
  - ヘルス判定ロジック

- `core/dashboard`
  - API 型追加
  - 状態/ヘルス/ジョブ表現ヘルパー
  - ホーム画面再設計
  - アプリ一覧カード化
  - 詳細画面の運用 UI 化
  - 追加フロー導線改善
