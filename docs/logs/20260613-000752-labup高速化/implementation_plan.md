# 実装計画

## 方針

配信方式は引き続き `build + preview` を維持し、ホットリロードやコンテナ内部コード差し替えは行わない。その代わり、起動コストの大きい処理を分離し、再実行が必要なものだけを走らせる。

## 実施項目

1. 開発用 Node イメージを作り、`apk add` をコンテナ起動のたびに実行しないようにする
2. 依存同期スクリプトを追加し、`package.json` / `yarn.lock` 系に変更があるときだけ `yarn install --immutable` を走らせる
3. `lab:up` 時は backend / dashboard コンテナを `--force-recreate` して、最新ソースを毎回起動時ビルドへ反映させる
4. `environment:lab:up` を 2 回実行し、初回と 2 回目以降の挙動を確認する

## 期待効果

- 新規依存追加がない通常の修正では、重い依存インストールをスキップできる
- `lab:up` を実行すれば、古い `dist` のまま残る事故を防ぎやすくなる
- 開発中でも本番同様の静的配信フローで動作確認できる
