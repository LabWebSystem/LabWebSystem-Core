# ADR-006: Core ReleaseをCompose単体で再生成可能な最小契約へ統一する

Status: ACCEPTED
Context: 旧Production契約はconfig.yaml、Caddyfile、Docker labels、image/migration/schema情報を含むmanifestを使い、lwsctlと手動導入で構成が分散していた。Core ReleaseはlwsctlがなくてもDocker Composeだけで導入・更新・再生成できる必要がある。
Decision: Git tagだけをversionの正本とし、Release assetを`release.json`と`compose.yaml`に限定する。manifestはversion、最低lwsctl version、Compose artifact名とchecksumだけを持つ。ホスト設定はruntime.envの`LWS_VERSION`、`LWS_PRIMARY_DOMAIN`、`LWS_INSTALLATION_ID`、`LWS_DATA_DIR`へ集約し、Composeを本番構成の唯一の正本とする。
Rejected: config.yamlやCaddyfileを追加assetとして維持する案、manifestにimage/migration/schemaを重複記録する案、lwsctl専用の実行構成を持つ案は、手動導入とCLI導入の乖離を生むため採用しない。
Consequence: lwsctlはRelease取得、runtime.env作成、Compose pull/up、health確認だけを自動化する。Release workflowはtag起点で両imageをmulti-arch公開し、既存Releaseの上書きやvisibility変更をしない。
Related: SUP-001; CHG-010
CurrentValue: current
FutureRelevance: reusable
ValidityScope: Core production deployment / GitHub Release / lwsctl integration
