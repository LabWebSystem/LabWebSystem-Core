# ADR-008: deploy は明示バージョン指定と確認付きRelease再作成を行う

Status: ACCEPTED
Context: release tagがHEADに存在することだけを前提にしたdeploy taskでは、新規Releaseの開始に手動tag操作が必要であり、既存tag / Releaseを再利用する手順も統一されていなかった。
Decision: 公開入口を `mise run deploy --version vX.Y.Z` とし、厳格なSemVer形式を検証する。git、GitHub CLI、gh認証、clean working treeを確認し、既存tagまたはReleaseがある場合はTTYで削除確認を行う。確認後にRelease（cleanup-tag）またはremote/local tagを削除し、指定tagを作成してpushする。
Rejected: VERSIONを暗黙にRelease versionとして使用する案は、再Releaseや将来versionの指定を明示できず、誤deployの対象が不明瞭になるため採用しない。既存tag / Releaseを無確認で上書き・削除する案は、Production artifactの破壊につながるため採用しない。
Consequence: deploy実行にはgh認証とpush権限が必要になる。既存Releaseの再作成は明示確認を要求する。Release workflowはvX.Y.Z形式を受け付ける。
Related: CHG-014; SUP-003; ADR-006; ADR-007
CurrentValue: current
ValidityScope: Core Release tag / GitHub Release / `mise run deploy`
