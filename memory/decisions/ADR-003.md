# ADR-003: アプリ runtime は application_id 配下へ閉じ込めて正規化 Compose のみ実行する

Status: ACCEPTED
Context: 既存 backend は `application_id` を DB 主キーとして持ちながら、Git clone 先・appdata・Compose project 名には `name` を混在利用していた。さらにアプリ側 Compose をほぼそのまま `docker compose` へ渡していたため、bind mount・named volume・build/context・env_file・secrets/configs.file・ports・devices などからホスト参照や危険設定が入り込めた。
Decision: runtime 実体の基準を `application_id` に統一し、`runtime/apps/<application_id>/{src,data,.lab-core}` をアプリ専用 root とする。Compose 実行前に `.lab-core/docker-compose.normalized.yaml` を生成し、bind mount は application root 内へ再解決、named volume は `data/volumes` bind へ変換、`ports`・`devices`・`privileged`・`host` namespace・Docker socket 系などの危険設定は backend 側で拒否する。Compose project 名もアプリ名ではなく `application_id` 由来の `lws-*` 形式に寄せる。
Rejected: アプリ側 Compose の自由度を維持したまま allowlist を追加する案は、bind mount 以外のホスト参照経路を塞ぎ切れず安全境界が曖昧になるため採用しない。`runtime/appdata/<name>` を残したまま source だけ `application_id` 化する案は、削除境界と監査単位が二重化するため採用しない。
Consequence: backend は source Compose を直接実行せず、毎回正規化済み Compose を `.lab-core` 配下へ生成して使う。アプリ名変更は runtime path や Compose project 名に影響しない。既存の `runtime/appdata` 前提は新 runtime layout の判断基準としては扱わない。
Related: ADR-001
CurrentValue: current
ValidityScope: backend の application runtime layout / compose 実行ポリシー / app root 削除境界
