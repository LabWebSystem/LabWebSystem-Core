# ADR-001: Backend API を Operation 中心へ破壊的に統一する

Status: ACCEPTED
Context: 既存 backend は `/api/jobs` と `POST /api/applications/{applicationId}/restart` などの操作別 API が並存し、Route/Service/DB の責務が Job と Application にまたがっていた。仕様変更書では Operation を正式な実行単位とし、旧 Job API と旧操作 API を互換レイヤーなしで置き換えることを要求している。
Decision: backend の正規実行単位を `Operation` に統一し、外部 API・内部 Service・Repository・DB テーブルを `operations` ベースへ移行する。`/api/jobs` 系 API と `applications/{id}` 直下の旧操作 API は新実装で提供しない。Application 削除も `type: delete` の Operation として扱い、通常 API の `DELETE /api/applications/{applicationId}` は外す。
Rejected: 旧 `/api/jobs` と旧操作 API を互換レイヤーとして残す案は、状態管理と UI 参照先の二重化を継続させるため採用しない。
Consequence: DB migration、Operation Repository/Service/Runner、OpenAPI、README、frontend の API 参照更新を同一変更系で進める必要がある。Operation と Application の状態は分離し、旧 Job 呼称の参照箇所を追跡して置き換える。
Related: # LabWebSystem-Core バックエンド仕様変更案 v1.0（確定版）
CurrentValue: current
ValidityScope: backend API / DB schema / dashboard API 参照の基準線
