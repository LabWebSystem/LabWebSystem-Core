# ADR-009: Production の公開入口を Core 管理 Caddy に統一する

Status: ACCEPTED
Context: Production Compose が dashboard の port 80 を host へ直接 publish しており、`dashboard.<primary-domain>` 向けに生成する DNS / Caddy 設定は実行中の proxy に適用されていなかった。この状態では dashboard、backend、登録 Application の公開経路を一貫して制御できない。
Decision: Production Compose は Caddy proxy を含み、host に publish する port は proxy の HTTP/HTTPS だけとする。dashboard と backend は Compose network 内に閉じ、Caddyfile は Backend が生成して proxy が reload する。proxy は登録 Application の upstream が参加する Docker network にだけ接続する。
Rejected: dashboard を `0.0.0.0:80` で直接公開する案、利用者に別途 host proxy の構成を要求する案は、Core Release 単体で再生成できる契約と hostname routing の一貫性を失うため採用しない。
Consequence: Production host は proxy 用に 80/443 を利用可能にし、TLS certificate の永続 volume を保持する。DNS は公開先を決めるだけで認証境界にはならないため、dashboard の認証は別途必須とする。
Related: ADR-006; CHG-010; CHG-012
CurrentValue: current
ValidityScope: Core production Compose / lwsctl installation / public dashboard and Application routing
