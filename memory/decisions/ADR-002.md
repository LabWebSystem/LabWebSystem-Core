# ADR-002: Operation SSE は単一 backend 前提の in-memory pub/sub で開始する

Status: ACCEPTED
Context: 仕様変更書では `GET /api/operations/{operationId}/logs/stream` による SSE を求めている一方、初期実装は単一 backend インスタンス前提としている。SQLite polling でリアルタイム配信すると DB 負荷と遅延が増えやすい。
Decision: Operation Log / Step / Operation のリアルタイム配信は、初期実装では backend プロセス内の in-memory pub/sub で行う。永続化の正本は `operation_logs` / `operation_steps` / `operations` とし、再接続時は snapshot + after 差分取得で補完する。
Rejected: SQLite polling を SSE の正本にする案は、Runtime Log / Operation Log の高頻度表示時に不要な polling 負荷が乗るため採用しない。初期段階から Redis/NATS を必須化する案は、単一 backend 前提に対して運用コストが過剰なため採用しない。
Consequence: `OperationEventBus` を interface 化し、将来 multi-instance 化するときに Redis/NATS 等へ差し替え可能な境界を残す。terminal status 時は operation event を1回送って stream を閉じる。
Related: ADR-001
CurrentValue: current
ValidityScope: Operation SSE / log streaming / backend 単一インスタンス前提
