# CHG-006: application_id ベース runtime・Compose サンドボックス・app root 削除 helper を追加

Status: ACTIVE
Reason: アプリ名依存の runtime path と、source Compose をそのまま実行する方式では、bind mount によるホスト参照や削除境界の曖昧さが残っていた。bind mount 配下の root 所有ファイルも通常の `fs.rmSync` では安全に消せないケースがあった。
Change: backend に `application_id` ベースの runtime path helper と lower-case application id 生成を追加し、repository/data/.lab-core を `runtime/apps/<application_id>` 配下へ集約した。さらに deploy/update/restart/stop/resume/rebuild/delete で `.lab-core/docker-compose.normalized.yaml` と `.lab-core/compose.env` を生成するようにし、bind mount の application root 変換、named volume の `data/volumes` 変換、`ports` / `devices` / `use_api_socket` / `privileged` / host namespace / Docker socket 系の拒否を backend 側で強制した。加えて `core/backend/scripts/delete-app-root.mjs` を追加し、`full` delete 時は app root 単位で helper 経由削除するよう変更した。
